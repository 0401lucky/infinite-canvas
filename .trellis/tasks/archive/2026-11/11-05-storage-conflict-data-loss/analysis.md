# Bug Analysis: 单页面版本竞态与同步丢失修改

## 1. Root Cause Category

- E / 隐含假设：原队列只隔离同键任务，却假设先等待已有任务就能安全读取/替换集合；后来进入的本页面写入仍可交错，旧读取响应可能覆盖更新的修订缓存。
- B / 跨层契约：WebDAV 用较早的内存快照应用合并结果，再以全局重新加载刷新历史；这个动作同时重置业务内存、会话请求、页面挂载键和未持久化工作台输入。
- D / 测试覆盖缺口：服务端 CAS/账号隔离不能证明前端 Promise 顺序正确，原有测试没有覆盖集合屏障、下载期间编辑、跨领域同键媒体或同步后页面存活。
- 提示把所有存储/媒体版本冲突归因于其他页面，不能据此断定其他人登录。基线 `0d2676b` 的源码能确认这些风险，用户部署中的具体触发过程仍未运行复现。

## 2. Why Fixes Failed

本任务没有执行过多轮线上修复/测试，不编造先前失败记录。两种必须避免的表面修法是只隐藏错误提示，或在 409 后取最新版本号覆盖旧数据；前者留下保存失败，后者破坏数据保护。

取消同步全局重载时还必须保留原有节点/助手/封面的媒体恢复与历史更新，否则会出现空 URL 图片不显示或导入历史不可见。这些行为已改为就地执行，不扩大存储/兼容范围。

## 3. Prevention Mechanisms

| Priority | Mechanism | Specific Action | Status |
| --- | --- | --- | --- |
| P0 | 队列结构 | 精确命名空间分组，集合任务调用时登记屏障，缓存更新后再放行后续记录任务 | 已实现 |
| P0 | 快照归属 | 历史替换保留原修订，真实变化继续拒绝，不用新修订重试旧集合 | 已保留 |
| P0 | 页面保数 | 媒体恢复后再合并当前画布/素材，成功集合替换就地通知历史，不重置页面 | 已实现 |
| P1 | 会话归属 | 新 epoch 脱离旧队列，旧响应/清理/通知不能影响新会话；同步时间和提示检查原信号 | 已实现 |
| P1 | 回归用例 | 新增 8 项队列与 4 项同步受控用例，覆盖并行、真实冲突、编辑/删除、恢复与取消 | 代码已补，未运行 |
| P1 | 人工验收 | 确认单页面连续保存、同步期间操作、工作台输入和进行中的视频任务 | 待用户验证 |

## 4. Systematic Expansion

- 同类消费者包括历史读取、插件记录和提示词缓存；它们复用共享适配器的屏障，不在各页面添加临时重试或版本补丁。
- 媒体恢复函数在图片列表与主图之间也有 await，已补原会话检查，防止旧恢复继续从新账号读取键。
- 源码静态审阅不是运行证据；没有操作用户数据库、真实 WebDAV、现有浏览器页面或部署。
- 四个同步领域仍可能部分成功，不增加全局事务、自动回滚、跨端删除策略或新边界参数。
