# 存储冲突与同步保数设计

## 边界与现有契约

- 前端持久化继续由 `web/src/lib/server-storage.ts` 管理，服务端保留 SQLite 事务和 `If-Match` 比较交换；不改数据库结构、认证、媒体清理规则或业务存储位置。
- 继续保留每条记录的队列和画布 400ms 防抖。修复集合操作所需的排队依赖，不设置新的全局并发、超时或重试边界。
- WebDAV 继续按画布、素材、生图历史和视频历史四个领域同步；不承诺四个领域整体原子化。记录失败不变成空数据或成功，不强制覆盖真实冲突。
- 用户手动重新加载仍使用现有放弃未保存修改的确认；登录、退出、账号切换和图片清理的专用重置流程不改。

## 1. 集合队列屏障

当前记录键队列只隔离同一条记录；`readAll` 的等待发生在入队之外，集合替换又使用独立键，不能隔离随后进入的记录任务。

在同一个现有队列管理器中区分记录任务和集合任务：

1. 记录任务等待此前同键任务以及此前的集合任务。
2. 集合读取/替换在调用时立即入队，等待此前本命名空间的任务；后续记录任务等待该集合任务。
3. 集合响应的版本记忆在屏障内完成，然后才放行后续写入；不能先放行再写缓存。
4. 不同记录且无集合屏障时仍可并行；不同命名空间不相互阻塞。
5. 前序任务失败后队列可继续处理，但失败标记仍保留；新任务只有实际保存成功才能确认对应键。
6. 每个任务持有原会话 epoch/signal；旧会话的完成不能更新缓存、状态或通知。

`replace(items, revision)` 继续使用调用方所依据快照的版本。排队期间如果其他写入改变该快照，仍返回冲突，不能用新读取的版本搭配旧 `items`。

## 2. 同步不重置页面

删除 WebDAV 完成后调用 `reloadData()` 的路径。画布和素材本就在当前 store 中应用，历史集合成功替换后通过存储适配器提供的本页面集合变更订阅通知工作台刷新；不使用浏览器跨页广播，不改变用户会话，也不增加整页挂载键。

生图和视频页直接订阅相应存储入口，保留各自现有保存/恢复生成逻辑。历史读取在页面内持有递增的请求归属，媒体 hydration 完成后只让最新读取更新列表，避免旧读取结果晚到覆盖新列表。视频恢复仍沿用现有 active-log 去重，不能因为通知额外创建生成任务。

手动视频生成在保存待处理记录期间先占用既有 active-log 标记，保存结束后在同一同步片段中交给原轮询入口；避免同步触发的自动历史恢复先接管该任务、丢掉提交时的 Agent 归属或配置。

存储订阅只表示集合已经成功替换，不宣称普通请求或失败替换成功；监听回调不得让已成功的持久化被重新标记为失败。

## 3. 应用同步结果时保留最新本页面数据

- 画布：下载结束后复用现有节点/助手媒体 hydration，恢复空 URL 的存储键引用，再在同步写入当前 store 的同步片段中重新读取当前 projects/deletedProjects，沿用 `mergeCanvasData` 的更新时间与删除标记规则合并，保住期间的编辑、新建和删除。
- 素材：先完成需要的媒体与自定义封面 hydration，再读取当前 assets 合并并应用；不能在 hydrate 的 await 之前固定最终本页面快照。
- 让 `applyData` 返回实际应用的数据，后续文件收集和远端清单序列化基于该结果，而不是再次使用更早的合并结果。
- 历史：保留原快照的 CAS 版本；如本页面生成或其他页面修改导致版本改变，失败并保留已保存的新增记录，不用自动重读修订号强行替换旧数据。
- 同步上传期间发生的更晚修改仍正常持久化，不回头重置本页面；远端清单可以等下一次用户主动同步，不承诺持续实时同步。

同次同步的多个领域共享一个按 storageKey 去重的缺失媒体下载 Promise 表，作用域限于这一次同步。先登记任务再开始异步下载，其他领域复用同一任务；继续使用原会话信号、既有文件并发值和已清理键检查，不增加自动重试或让旧会话复用新会话任务。

## 4. 冲突文案与失败语义

服务端和中英本地化统一改为来源中性的版本冲突提示，强调当前修改尚未保存、不要直接刷新丢弃内容。媒体冲突保留媒体语义，不能本地化后又被断言为其他页面操作。

保持现有失败存储状态与 flush 的失败传播。真正冲突时不自动刷新、不移除未保存标记、不把旧数据写到最新版本，也不新增浏览器业务缓存。已有手动放弃并重新加载仍是有明确提示的用户选择；本任务不承诺自动恢复或导出所有未保存数据。

同步按钮沿用开始时的会话信号，在异步完成后检查再写 lastSyncedAt 或提示成功；退出后的旧同步不能修改下一账号的配置或显示误导性完成提示。

## 范围与风险

- 主要代码：存储适配器、WebDAV 同步、生图/视频历史刷新、冲突文案。业务 store/API 只在必要时修改，不顺手调整无关界面。
- 新测试沿用 `web/tests/` 的 Bun 模式，使用模拟请求和受控 Promise，不访问用户数据库或真实 WebDAV。
- 单页面竞态是明确代码风险，但用户实际丢失仍需验收确认；不把静态推导当成线上复现。
- WebDAV 已成功的领域不会因为另一个领域失败自动回滚；失败信息应保留，下一次同步由用户主动触发。
- 队列屏障会使同一集合读取/替换与记录写入按顺序执行，这是正确性约束，不是新增全局吞吐上限。
- 无存储迁移；回退只撤销本任务的源代码改动，不删除 SQLite、媒体目录、Docker 数据卷或既有用户文件。
