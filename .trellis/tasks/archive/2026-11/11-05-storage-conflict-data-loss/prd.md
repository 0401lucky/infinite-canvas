# 修复单页面保存版本冲突与数据丢失

## Goal

修复用户独自使用时频繁出现的存储版本冲突，避免保存失败或同步刷新使当前修改丢失。

## Background

- 用户报告账号未被朋友同时登录，仍反复出现“数据已在其他页面更新”提示，并伴随数据丢失。
- 首次拉取因本机无法解析 `github.com` 失败，重试 `git pull --ff-only` 成功并显示已是最新；调查基于 `main` 的 `0d2676b`，既有未跟踪研究文件保留不动。
- 以下缺陷由静态代码排查确认存在；尚未复现用户实际部署中的丢失过程，不能宣称已确认唯一触发原因。

## Requirements

- R1（P1）：修复本页面自身请求导致的版本倒退和持续保存冲突。记录读写已按键排队，但集合读取只先等待现有任务，随后可与新增写入交错，读取响应直接更新版本缓存；集合替换使用另一个队列键，也未与后续单记录写入互斥（`web/src/lib/server-storage.ts:9`、`web/src/lib/server-storage.ts:41`、`web/src/lib/server-storage.ts:45`、`web/src/lib/server-storage.ts:100`）。保留不同记录之间现有并行能力。
- R2（P1）：同步不能未经确认就重置业务内存、页面输入和进行中的生成状态；失败必须保持可见，不作为保存成功。现有 WebDAV 结束时调用重新加载，重置业务状态并改变页面挂载键（`web/src/services/app-sync.ts:141`、`web/src/stores/use-user-store.ts:70`、`web/src/layouts/user-layout.tsx:29`）。同步完成后只刷新受影响的列表。
- R3（P1）：同步期间的新建、编辑、画布删除和生成结果不能被早先读取的快照静默覆盖。画布和素材在下载媒体后直接应用之前的合并结果（`web/src/services/app-sync.ts:101`、`web/src/services/app-sync.ts:114`、`web/src/services/app-sync.ts:168`、`web/src/services/app-sync.ts:175`）。同次同步的多个领域引用同一媒体时，不重复下载并发写回同一键（`web/src/services/app-sync.ts:96`、`web/src/services/app-sync.ts:219`、`web/src/services/app-sync.ts:250`）。无法安全应用历史集合时明确停止该步骤，而不是覆盖。
- R4（P2）：冲突提示准确表达“版本冲突、当前修改未保存”，不能断言有人在其他页面操作；真正的过期写入仍拒绝，不能取新版本号重试旧数据。当前服务端和本地化文案把所有冲突统一归因于其他页面（`server/src/storage.ts:83`、`server/src/media.ts:33`、`web/src/i18n/locales/zh-CN.ts:38`）。手动丢弃修改重新加载保留现有明确确认。
- R5：只修改相关持久化、同步、历史刷新和文档；沿用 Bun 测试模式补回归测试代码，但不自动执行测试、语法/类型检查、格式化或构建，不提交或部署。

## Acceptance Criteria

- [ ] AC1 / R1：控制请求先后顺序，交错集合读取、单记录写入和集合替换，本页面缓存不会被旧响应倒退；连续保存后刷新可恢复最新数据，不同键无集合操作时仍可并行。
- [ ] AC2 / R2：同步成功或失败都不重新挂载工作台，不清空当前提示词、参考、结果或进行中的生成；服务端保存失败仍保留错误和未保存状态。
- [ ] AC3 / R3：在同步下载期间新建或修改画布/素材、删除画布、完成生成，较新的本页面数据不会被旧结果覆盖；历史修订发生变化时停止过期替换而不丢记录。
- [ ] AC4 / R1、R2：同步导入的历史在当前工作台就地更新；多个历史刷新响应交错时，旧结果不能覆盖新列表。
- [ ] AC5 / R3：画布、素材和历史共同引用一个缺失媒体键，同次同步只下载保存一次；已清理图片不恢复。
- [ ] AC6 / R4：其他页面确实更新后，冲突仍保留服务端权威数据和本页面当前修改，提示不误判来源；仅用户明确确认才丢弃当前修改重新加载。
- [ ] AC7 / R5：退出、切换账号和图片清理仍遵循会话隔离及媒体清理契约；回归测试和待用户测试事项就绪，不声称未运行的验收已通过。

## Out Of Scope

- 不新增实时多人协作、业务浏览器存储、自动数据迁移或强制覆盖冲突的重试。
- 不更改现有超时、并发、大小限制或重试次数。
- 不改变素材和生成历史的跨设备删除策略，不提供跨四个 WebDAV 领域的整体事务或自动回滚。
- 不承诺找回已经丢失的数据，不自动提交、部署或操作用户正在使用的浏览器页面。
