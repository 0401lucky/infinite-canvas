## Administrator and Server Storage

Implementation is ready for manual acceptance; no syntax/type checks, tests, builds, or Docker validation were run. These items replace the old browser-storage statistics/quota checks. The two unrelated Agent TODO items remain unchanged, and formal feature documentation is not promoted before acceptance.

- Authentication and startup: first start without an explicit administrator password must fail; wrong credentials create no session. Before login, direct access to private records, originals, and previews must fail without revealing resource existence, and prompt/plugin/Agent business effects must not start. URL credentials must leave the address bar immediately and be applied only once after successful authenticated loading.
- Session lifecycle: correct login, refresh restoration, logout, credential changes, and fixed 7-day expiry should work. Test logout/expiry/reload during prompt fetch, plugin discovery/import, upload, polling, and queued writes; old work must not write into a later session, activate plugins, or remove a newer refresh promise. HTTPS uses a Secure/HttpOnly/SameSite cookie; write Origin mismatch is rejected. No IP/alternative login throttling is added.
- Persistence and failure: save configuration/API keys, projects, assets, workbench histories, prompt sources/caches, and plugin JSON, then refresh or sign in from another browser. Failed loading must not open editable empty state; disconnected/read-only storage and failed flush must report failure without browser fallback or success messages. Existing browser databases must neither migrate nor be deleted automatically.
- Conflicts and snapshots: two browsers editing the same record or a WebDAV history collection should return 409 for stale revisions and preserve the server authority. Collection replacement must be atomic and use the revision captured with the data being merged; deletion revisions must remain. Reload after conflict is explicit, not automatic whole-document merging.
- Original media: upload/generate images, video, and audio, refresh, and verify preview/playback/download/edit/reference/export. An empty saved `content`/`dataUrl` with a valid key must restore. Downloads use the original, not a 768px preview; immediate canvas-to-assets downloads and Chinese filenames should work. Application `/api` bypasses the AI proxy. Invalid/CORS-blocked originals or storage failure must not become fake saved images/videos.
- Real space and cleanup: Server storage replaces Local storage/browser quota. Check image/preview counts and original/preview/media/database/temporary-file bytes against actual files, including HTTP deployments without `navigator.storage.estimate`. Clear all images requires an irreversible-action confirmation and includes referenced canvas/asset/history images and covers; old entries show cleared and cannot preview/download/become valid references. Account/config/API keys/project structure/text/video/audio/local Agent history must remain.
- Partial cleanup and stale clients: simulate a file deletion failure; the operation must report incomplete cleanup and remaining files must still count toward usage, with a later manual cleanup possible. Cleared keys, stale JSON, old URLs, and pending previews must not revive images. Other already-open browsers need refresh to show the new state; this is not real-time collaboration.
- ZIP and WebDAV: cleanup must not delete remote backups or let WebDAV automatically refill tombstones. ZIP export preserves cleared entries without stale content; a missing non-cleared original fails export. Explicit import of a backup containing originals allocates new keys and remaps nested node/asset/reference/cover keys; importing cleared-only entries keeps their state. A declared file absent from the ZIP fails import.
- Approved boundaries: fixed 7-day sessions, 512 MiB per upload, and 32 MiB JSON writes. In an independent test deployment, temporarily lower configurable limits to verify 413 and no truncated overwrite/incomplete upload, then restore approved values; do not introduce new production limits, retries, or concurrency changes.
- Docker and security: verify Node 24 native SQLite/Argon2 dependencies, non-root writable complete data volume, container restart/update persistence, SPA routes, plugin assets, public analytics-only `config.js`, private directory isolation, and media Range/416 responses. Root `.env` must require explicit credentials and match the external `APP_ORIGIN`; do not remove the volume during updates. SQLite/API keys/env/backups are sensitive and keys remain readable by signed-in browsers. Static-only Render/Vercel deployment is not adapted or claimed verified.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 请求应带 aspectRatio（所选比例）；分辨率选了 1K / 2K / 4K 时应按尺寸表带上 imageConfig.imageSize，选自动时不带。质量不参与分辨率换算，视频尺寸设置保持原有行为。
- 图像质量可选自动与 5 档（低 / 中 / 高 / 极高 / 最高），请求里的 quality 字段应与所选档位一致，且尺寸不随质量变化。
