# Local Development

The React application lives in `web/`; `server/` provides administrator authentication, SQLite records, and private media files. The browser still sends AI requests directly to the user's provider. The new flow remains subject to manual acceptance.

## Configure and start the API

From the repository root, copy `.env.example` to `.env` and set a strong `ADMIN_PASSWORD`. Use Node.js 24 or newer. `APP_ORIGIN` defaults to `http://localhost:3000` and must match the browser origin.

```bash
cd server
npm ci
npm run dev
```

The API defaults to port `3001` and reads the root `.env`. Business data defaults to the repository's private `data/` directory; do not put it under `web/` or publish it as static assets.

## Start the frontend in another terminal

```bash
cd web
bun install
bun run dev
```

Open `http://localhost:3000`, sign in, and configure your provider. Vite proxies `/api` to the API port from the root `.env`; private API requests do not use the AI proxy. Both processes must remain running. Loading/saving errors are visible and do not enable IndexedDB/localStorage fallback. Old browser data is not migrated.

## Start the documentation site

```bash
cd docs
bun run dev
```

Common locations:

- Canvas, pages, and interactions: `web/`
- Authentication, SQLite, media, and space cleanup: `server/src/`
- Browser persistence adapter and session lifecycle: `web/src/lib/server-storage.ts`, `web/src/stores/use-user-store.ts`
- Prompt caching: `web/src/services/api/prompts.ts`
- Documentation content: `docs/content/docs/`
