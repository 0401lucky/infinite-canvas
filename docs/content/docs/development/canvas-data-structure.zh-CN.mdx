# 画布数据结构

本文档说明个人版已实施的数据结构和存储流程；认证、持久化、清理与部署效果仍需按[待测试事项](/zh-CN/docs/progress/pending-test)验收。

## 当前存储位置

配置和业务数据由 `server/` 提供的认证同源 API 保存，不再持久化到浏览器业务数据库：

| 数据 | 存储所有者 |
| --- | --- |
| 配置、API Key、画布项目、素材、提示词来源、插件清单 | SQLite `records` 表的 `app_state` 命名空间 |
| 图片/视频工作台记录、提示词缓存 | SQLite 的 `image_generation_logs`、`video_generation_logs`、`prompt_cache` 命名空间 |
| 插件私有 JSON | SQLite 的 `plugin:<pluginId>` 命名空间 |
| 图片原文件、预览、视频、音频和其他媒体 | 私有文件目录与 SQLite `media` 元数据 |
| 管理员与会话 | SQLite `admin`、`sessions` 表 |

画布和素材的记录 key 仍为 `infinite-canvas:canvas_store`、`infinite-canvas:asset_store`。完整数据目录包含 `app.sqlite` 及 SQLite 关联文件、`media/images/`、`media/files/`、`previews/` 和临时 `uploads/`，必须放在 `web/` 之外，不能作为静态目录公开。

业务 store 在会话确认后手动补水，加载失败不能当作空数据成功，保存失败不能回退 IndexedDB/localStorage。浏览器仅保留主题、语言等极小的本机偏好；不自动迁移或删除旧浏览器数据库。本地 Canvas Agent 的消息历史和独立存储版本规则保持不变。

## 画布项目结构

每个画布项目是一个 `CanvasProject`：

```ts
type CanvasProject = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
};
```

字段说明：

- `id`：画布项目 ID，当前前端生成。
- `title`：画布名称。
- `createdAt` / `updatedAt`：ISO 字符串。
- `nodes`：画布节点列表。
- `connections`：节点连线列表。
- `chatSessions`：右侧画布助手会话。
- `activeChatId`：当前选中的助手会话 ID。
- `backgroundMode`：画布背景模式。
- `showImageInfo`：图片信息的显示设置。
- `viewport`：视口变换，`x/y` 是屏幕平移，`k` 是缩放比例。

画布 store 还保存 `deletedProjects`，供既有 WebDAV 画布删除同步使用；它与媒体清理 tombstone 是不同状态。

## 节点结构

每个节点是一个 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  id: string;
  type: CanvasNodeTypeId;
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: CanvasNodeMetadata;
};
```

通用字段：

- `id`：节点 ID。
- `type`：节点类型，内置图片、文本、生成配置、视频、音频、组六类，也允许 `pluginId:name` 这样的扩展 ID。
- `title`：节点标题。
- `position`：画布世界坐标，不是屏幕坐标。
- `width` / `height`：画布世界坐标下的节点尺寸。
- `metadata`：节点内容和业务状态。

`metadata` 当前常用字段：

```ts
type CanvasNodeImage = {
  id: string;
  status: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  content: string;
  storageKey?: string;
  cleared?: boolean;
  naturalWidth: number;
  naturalHeight: number;
  bytes: number;
  mimeType: string;
};

type CanvasNodeMetadata = {
  content?: string;
  prompt?: string;
  status?: "idle" | "success" | "loading" | "error";
  errorDetails?: string;
  fontSize?: number;
  generationMode?: "text" | "image" | "video" | "audio";
  model?: string;
  size?: string;
  count?: number;
  naturalWidth?: number;
  naturalHeight?: number;
  freeResize?: boolean;
  images?: CanvasNodeImage[];
  primaryImageId?: string;
  inputOrder?: string[];
  storageKey?: string;
  cleared?: boolean;
  mimeType?: string;
  bytes?: number;
  videoTaskId?: string;
  videoTaskProvider?: "openai" | "gemini";
};
```

不同节点的使用方式：

- 图片节点：`content` 是运行时展示 URL，长期身份是服务端 `storageKey`；`naturalWidth/naturalHeight/bytes/mimeType` 保存原图信息，已清理时保留键并标记 `cleared`。
- 视频、音频节点：`content` 是运行时播放 URL，`storageKey` 指向服务端原文件；视频异步任务保存远端任务 ID 与提供商，供刷新后继续查询。
- 文本节点：`content` 保存文本内容；`fontSize` 保存字体大小；`prompt/status/errorDetails` 保存生成状态。
- 生成配置节点：`generationMode/model/size/count/inputOrder` 等字段保存生成配置；上游输入通过 `connections` 计算。
- 多图图片节点：批量生成仍只保存为一个图片节点，请求开始前会在 `images` 中创建全部图片槽位，每个槽位通过 `status/errorDetails` 独立记录实时状态，成功后补充图片数据；最先成功的槽位会立即写入 `primaryImageId`，并由节点级 `content` 和图片元数据展示；展开状态仅属于当前界面，不写入项目数据。

这里展示的是常用字段，完整类型以 `web/src/types/canvas.ts` 为准。持久化入口会移除带存储键的临时 `blob:` URL，因此记录中的 `content` 可以为空；不能因为 URL 为空就跳过有效 `storageKey` 的恢复。

## 连线结构

每条连线是一个 `CanvasConnection`：

```ts
type CanvasConnection = {
  id: string;
  fromNodeId: string;
  toNodeId: string;
};
```

连线只保存节点 ID，不保存端口坐标。渲染时根据节点位置和尺寸计算路径。

删除节点时会同步删除以该节点为起点或终点的连线。删除图片组根节点时，会把对应子节点一起删除。

## 助手会话结构

助手会话保存在画布项目内：

```ts
type CanvasAssistantSession = {
  id: string;
  title: string;
  messages: CanvasAssistantMessage[];
  createdAt: string;
  updatedAt: string;
};
```

图片引用和助手生成图片也遵循同一套图片存储规则：

- `dataUrl` 仅供运行时展示，不是持久化文件身份。
- `storageKey` 存在时，以该键读取认证后的原文件，不回退旧 URL。
- 发送到浏览器直连的 AI 接口前，如果需要 base64，通过 `imageToDataUrl` 临时转换原文件。

这指画布内助手的项目数据，不把本机 Agent 的 thread/turn/item 消息历史并入应用数据库。

## 图片写入流程

所有新增图片应通过 `uploadImage(input)` 写入：

1. 传入 `Blob`、data URL 或远程 URL，读取真实原文件。
2. 验证 Blob 可解码为图片，读取原始宽高。
3. 生成 `image:<id>` 新键，经同源 `/api/media` 上传并保存元数据。
4. 原文件保存成功后，缓存当前会话的 Blob 与 `blob:` URL，返回 URL、键及原图信息。
5. 沿用浏览器预览队列的 768px 最长边 / WebP 0.86 策略，预览单独保存在服务端。

```ts
type UploadedImage = {
  url: string;
  storageKey?: string;
  width: number;
  height: number;
  bytes: number;
  mimeType: string;
};
```

图片节点会通过 `imageMetadata(image)` 写入：

```ts
{
  content: image.url,
  ...(image.storageKey ? { storageKey: image.storageKey } : {}),
  status: "success",
  naturalWidth: image.width,
  naturalHeight: image.height,
  bytes: image.bytes,
  mimeType: image.mimeType
}
```

图片能通过远程 URL 显示，不代表原文件已经保存。下载、解码或服务端保存失败会报错，不伪造存储键或保存成功；跨域原文件下载可以使用既有本地代理，但应用 `/api` 和私有原文件接口不能经过 AI 代理。

## 媒体读取与缓存

打开画布或素材列表时按服务端键补水：

- 即使 `content`/`dataUrl` 为空，也通过 `resolveImageUrl` 或 `resolveMediaUrl` 恢复有效存储键，对应认证后的 `/api/media/.../original`。
- 原图下载、编辑、生成参考、ZIP 和 WebDAV 通过 `getImageBlob`/`getMediaBlob` 读取原文件，不能拿缩略图替代；下载反馈复用 `use-download-media.ts`。
- 缺失或已清理键返回不可用状态，不回退旧 blob URL、远程 URL 或备用封面。
- 预览不写入画布/素材/历史 JSON，也不进入 ZIP 和 WebDAV 备份。
- 退出、会话过期或重新加载数据时取消旧会话请求，释放对象 URL、预览和私有缓存；不自动补存旧 base64 或迁移浏览器数据。

## 图片移除与全量清理

普通删除仍按引用关系清理：删除节点、画布、素材或历史后收集剩余引用；服务端发现其他已保存记录引用该键时拒绝逐文件删除，避免误删共享原文件。

设置里的「清空全部图片」是另一种明确确认后的操作：

1. 先 flush 当前待保存数据，确认范围包括画布、素材、历史和参考中的所有已保存图片。
2. 服务端分阶段删除图片原文件和预览，SQLite 保留轻量 tombstone，清空旧展示 URL 并标记「已清理」。
3. 保留账号、配置、API Key、项目结构、文字、视频、音频和本机 Agent 历史。
4. 文件删除部分失败时明确报告未完成，剩余文件仍计入真实占用；可再次手动清理，不自动增加重试次数。
5. 清理后的键不能下载、预览、作为有效参考或被旧保存/WebDAV 补回；本机已下载文件和远端备份不在清理范围内。

## ZIP、WebDAV 与修订保护

ZIP 导出保留已清理记录而不打包旧文件；未被清理却缺失原文件时应报错，不静默生成缺文件备份。主动导入含原文件的 ZIP 会分配新媒体键并更新嵌套引用、参考和封面，不复活旧键；不含原文件的已清理记录继续保留该状态。

记录写入携带已读取的修订号，WebDAV 历史集合替换使用读取快照时的集合修订号并在事务中完成。冲突需要重新加载，不自动合并整份项目。其他已经打开的浏览器需要刷新才能看到清理状态，本版不提供实时协作或托管云同步。
